# 영화 검색 - 테스트 요구사항 문서

- 작성일: 2026-05-26
- 상태: 초안 (검토 대기)
- 대상 기능 문서: `영화검색.md`

## 1. 개요

`영화검색.md`에 정의된 영화 검색 기능에 대한 테스트 요구사항이다.
단위, 컴포넌트, 통합 세 레벨을 모두 다루는 풀 테스트를 목표로 한다.

테스트는 기능 PRD의 기능 요구사항(FR-1 ~ FR-4)과 성공 기준을 검증한다.
외부 OMDb API는 직접 호출하지 않고 MSW로 모킹하여, 테스트가 네트워크 상태와
무관하게 결정론적으로 동작하도록 한다.

## 2. 테스트 도구

| 도구                        | 용도                                 |
| --------------------------- | ------------------------------------ |
| Vitest                      | 테스트 러너, 단언(assertion)         |
| jsdom                       | 브라우저 DOM 환경 시뮬레이션         |
| React Testing Library       | 컴포넌트 렌더링과 DOM 질의           |
| @testing-library/user-event | 사용자 입력(타이핑, 클릭) 시뮬레이션 |
| @testing-library/jest-dom   | DOM 단언 매처(toBeInTheDocument 등)  |
| MSW (Mock Service Worker)   | OMDb API 요청 가로채기/모킹          |

- Vitest 환경은 `jsdom`으로 설정한다.
- 공통 셋업 파일에서 jest-dom 매처를 등록하고, MSW 서버를 테스트 수명주기에 연결한다.
  (`beforeAll` 시작, `afterEach` 핸들러 초기화, `afterAll` 종료)

## 3. 테스트 레벨과 대상

### 3.1 단위 테스트

OMDb API 클라이언트:

- `searchMovies(query, page)`
  - `apikey`, `s`, `page` 쿼리가 포함된 올바른 요청 URL을 구성한다.
  - 정상 응답에서 결과 배열과 `totalResults`를 반환한다.
  - `Response`가 `"False"`인 응답을 빈 결과로 구분해 반환한다.
- `getMovieDetail(imdbID)`
  - `apikey`, `i` 쿼리가 포함된 올바른 요청 URL을 구성한다.
  - 정상 응답에서 상세 객체를 반환한다.

무한 스크롤 다음 페이지 계산 (`getNextPageParam` 로직):

- 페이지당 10개를 기준으로, 지금까지 로드한 개수가 `totalResults`보다 작으면
  다음 페이지 번호를 반환한다.
- 로드한 개수가 `totalResults` 이상이면 `undefined`를 반환한다(더 불러올 페이지 없음).

### 3.2 컴포넌트 테스트

검색 폼:

- 키워드를 입력하고 엔터 또는 검색 버튼을 누르면 입력한 검색어로 제출 동작이 호출된다.
- 입력이 비어 있으면 제출 동작이 호출되지 않는다.

목록 항목:

- 포스터, 제목, 연도가 렌더된다.
- 포스터 값이 `"N/A"`이면 대체 표시(플레이스홀더)를 렌더한다.
- 항목은 `/movie/:imdbID` 경로로 이동하는 링크를 가진다.

상태 표시:

- 검색 전 초기 상태에서 검색 안내가 렌더된다.
- 로딩 중 로딩 표시가 렌더된다.
- 에러 상태에서 에러 표시가 렌더된다.
- 검색 결과 없음 상태에서 빈 결과 안내가 렌더된다.

### 3.3 통합 테스트

MSW로 API를 모킹한 상태에서 사용자 시나리오를 검증한다.

- 검색 실행 후 결과 목록이 화면에 표시된다.
- 다음 페이지를 불러오면 기존 목록에 결과가 누적된다.
- 목록 항목을 클릭하면 상세 페이지로 이동하고 상세 정보가 표시된다.
- 검색 결과가 없으면 빈 결과 안내가 표시된다.
- API 에러가 발생하면 에러 표시가 나타난다.
- URL `?s=검색어`로 진입하면 해당 검색 결과가 복원되어 표시된다.

## 4. 모킹 전략

MSW 핸들러로 OMDb 엔드포인트를 가로챈다.

- 검색(`?s=`):
  - 정상: `Search` 배열과 `totalResults`를 포함한 응답을 반환한다.
  - 페이지별 응답: `page` 쿼리에 따라 서로 다른 결과를 반환해 무한 스크롤 누적을 검증한다.
  - 결과 없음: `{ "Response": "False", "Error": "Movie not found!" }`를 반환한다.
  - 에러: HTTP 500 또는 네트워크 에러를 반환한다.
- 상세(`?i=`):
  - 정상: 상세 필드를 포함한 객체를 반환한다.
  - 에러: HTTP 500 또는 결과 없음 응답을 반환한다.

테스트 시나리오별로 핸들러를 덮어써(override) 정상/실패 경로를 각각 검증한다.

### IntersectionObserver 주의

무한 스크롤 감지에 `IntersectionObserver`를 사용하는 경우, jsdom에는 해당 API가
없으므로 테스트 환경에서 모킹해야 한다. 다음 중 하나로 처리한다.

- 공통 셋업에서 `IntersectionObserver`를 모킹하고, 통합 테스트에서 교차(intersect)를
  수동으로 트리거해 다음 페이지 로드를 검증한다.
- 또는 다음 페이지 로드 트리거를 별도 함수/훅으로 분리해 단위 테스트로 검증하고,
  통합 테스트에서는 해당 트리거를 직접 호출한다.

## 5. 테스트 시나리오와 요구사항 매핑

| 시나리오                                     | 검증 대상 | 레벨          |
| -------------------------------------------- | --------- | ------------- |
| 키워드 입력 후 엔터/버튼 제출 시 검색어 반영 | FR-1      | 컴포넌트      |
| 빈 검색어는 API 미호출                       | FR-1      | 단위/컴포넌트 |
| 검색 요청 URL 구성(apikey, s, page)          | FR-1      | 단위          |
| 검색 결과 목록 렌더                          | FR-2      | 통합          |
| 다음 페이지 누적                             | FR-2      | 통합          |
| 다음 페이지 존재 여부 계산                   | FR-2      | 단위          |
| 항목 클릭 시 상세 이동 및 상세 표시          | FR-3      | 통합          |
| 상세 요청 URL 구성(apikey, i)                | FR-3      | 단위          |
| 검색 전 안내 / 로딩 / 에러 / 빈 결과         | FR-4      | 컴포넌트      |
| 포스터 N/A 대체 표시                         | FR-4      | 컴포넌트      |
| URL `?s=`로 검색 상태 복원                   | 성공 기준 | 통합          |
